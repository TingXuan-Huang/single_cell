## Problem Statement

The project should not jump from the current small-model CellFM scaffold to a
1B or 4B parameter H200 run. The defensible research claim is:

> From-scratch brain-specialized CellFMs are worth training because they let us
> observe training dynamics and representation geometry directly, especially
> whether self-supervised embeddings preserve biological dynamics rather than
> collapsing cells into taxonomy labels.

Scaling laws, tokenization comparisons, and distributed training are useful, but
they are support analyses. The main claim is dynamics preservation.

## What Makes This Research Worth Doing

Recent single-cell foundation models such as Geneformer, scGPT, scFoundation,
CellFM, UCE, and Nicheformer show that the field is scaling quickly. The weak
point in the literature is not "someone has not trained a large enough model."
The weak point is that many claims depend on downstream benchmark scores, while
training dynamics, tokenization-controlled geometry, and collapse-versus-dynamics
behavior are rarely exposed.

This project should use its from-scratch status as the advantage:

- You own the training run, so loss curves and geometry trajectories are visible.
- You own the tokenization choices, so rank versus value-aware representations can
  be tested under controlled data and model-size settings.
- You own the evaluation suite, so PCA, scVI, external scFMs, and self-supervised
  CellFM embeddings can be compared on the same cells.
- You can stop before expensive scale if the biology metrics do not improve.

## Locked Premises

1. Scaling is not the claim.
   The claim is dynamics preservation. Scaling laws, tokenization, and H200
   systems work are secondary analyses after the core experiment produces usable
   evidence.

2. The 1M/3M/5M/10M sweep remains the next serious phase.
   The repo already targets this sweep. It is the cheapest way to learn whether
   tokenization and scale affect biological geometry.

3. The go/no-go gate for 30M+ is biological geometry, not MLM loss alone.
   Lower masked-gene loss is not enough if OPC cycling or other dynamic axes are
   erased.

4. External scFMs are baselines, not opponents.
   Geneformer, scGPT, UCE, scFoundation, and related models should be checked
   where possible, but the project claim is about from-scratch training dynamics
   and brain-specialized representation geometry.

5. Lightning/FSDP is a readiness track, not the immediate center.
   The current blocker is not a missing distributed framework. It is the MLM
   logits memory path and the need to finish the small ladder cleanly.

### Phase 1: Fix the Token-Transformer Memory Blocker

Goal: make `rank` and `value_bin` train at 1M/3M/5M/10M without full logits over
all sequence positions.

Design change:

- Compute gene-vocabulary logits only for masked positions.
- Current expensive shape: `(B, L, V)`.
- Desired shape: `(N_masked, V)`, where `N_masked` is about
  `B * L * mask_ratio`.
- For value-bin, compute value-bin logits only for masked positions too.

Rationale:

- The loss ignores non-masked positions via `ignore_index=-100`.
- Materializing logits at ignored positions wastes memory and caused the observed
  OOMs.
- This is more important than switching to Lightning right now.

Validation sequence:

```bash

  --cache-dir /tmp/cellfm_smoke_cache \

  --model-config configs/model/tiny_1m.yaml \
```

### Phase 3: Dynamics-Preservation Evaluation

Goal: make the primary claim measurable.

The current eval stack has geometry and collapse metrics. It needs a stronger
biology layer before any 30M/100M decision.

Required analyses:

1. Stable-state structure.
   Use SST, PV/Pvalb, and VIP/Vip inhibitory populations. Stable types should be
   separated without pathological over-collapse.

2. Dynamic OPC axis.
   Compute or load a cell-cycle score, then test whether OPC embeddings preserve
   a continuous/cyclic axis.

3. Collapse comparison.
   Compare supervised-heavy encoders (`hvg_dense`, `embedding_bag`) against
   self-supervised token encoders (`rank`, `value_bin`) on within-class variance
   and NC1.

4. Tokenization comparison.
   Compare `rank` versus `value_bin` at matched size. The key question is not
   only which has lower loss, but whether value-aware tokens preserve dynamic
   axes better.

5. Baseline comparison.
   Keep PCA-64 and scVI-32 as serious baselines. Do not claim transformer value
   unless it beats or complements these baselines on the biology metric.

Suggested output:

- `notes/dynamics_preservation_report.md`
- `notes/figures/opc_cycle_axis_<encoder>_<size>.png`
- `notes/figures/stable_state_geometry_<encoder>_<size>.png`
- `notes/figures/collapse_vs_dynamic_axis.png`
- `results` or `/gscratch` CSV containing one row per run and one column per
  biology metric.

Decision gate:

- If `value_bin` improves dynamics metrics over `rank` at 3M or 5M without
  losing stable-state separation, prioritize value-aware scaling.
- If all token transformers lose to PCA/scVI on dynamics metrics, do not scale
  the transformer yet. Improve objective or tokenizer first.
- If supervised baselines classify well but show stronger collapse, that supports
  the main hypothesis even if their accuracy is high.

### Phase 5: Secondary Analyses B, C, and D

Run these only after the dynamics report exists.

#### B. Scaling laws

Use 1M/3M/5M/10M runs first. Plot:

- Validation loss versus body parameters.
- Linear and kNN probe metrics versus body parameters.
- Dynamic-axis metric versus body parameters.
- Collapse metrics versus body parameters.

Claim to test:

> Loss and classification may improve before biological geometry improves.

Go/no-go signal:

- Scale is worth more compute only if dynamic metrics improve or remain stable
  while loss/probe metrics improve.

#### C. Tokenization

Minimum controlled comparisons:

- `rank_tiny_3m` versus `value_bin_tiny_3m`.
- `rank_tiny_5m` versus `value_bin_tiny_5m`.
- `rank_tiny_10m` versus `value_bin_tiny_10m`, if 10M is stable.

Claim to test:

> Value-aware tokenization should preserve continuous biology better than
> rank-only tokenization.

If value-bin does not win:

- Do not add continuous values immediately.
- First inspect whether value-bin loss is dominated by gene prediction, value-bin
  prediction, or classifier loss.

#### D. Systems readiness

Do this after the scientific gate, not before.

Readiness checklist:

- Throughput measured as cells/sec and tokens/sec.
- Peak VRAM measured per model size and encoder.
- Restart from checkpoint tested.
- Failed-job recovery documented.
- DataLoader workers and prefetching tuned.
- H200 cost estimate uses observed throughput, not guessed throughput.

Only after this checklist should the project add Lightning/FSDP or a custom
distributed loop.

### Phase 6: 30M and 100M Expansion Gate

Do not start 30M/100M because 10M completed. Start because the evidence says the
biology question benefits from scale.

Required green lights:

- The full 16-run v1.2 table exists.
- Token-transformer runs no longer OOM at 10M.
- `value_bin` or another value-aware method beats rank on at least one dynamic
  metric at matched scale.
- PCA/scVI baselines are included.
- External scFM baseline check has either run or has a documented blocker.
- The best candidate has a reproducible checkpoint and evaluation artifact.

30M plan:

- One encoder only, probably the best value-aware encoder.
- One seed first.
- Same WMB isocortex cache.
- Same evaluation suite.
- No H200 unless A40/L40S throughput makes the run impractical.

100M plan:

- Only after 30M improves a biological metric.
- Add activation checkpointing before distributed complexity if single-GPU memory
  is the first bottleneck.
- Add Lightning/FSDP only when model or batch size makes DDP/single-GPU
  insufficient.

1B/4B plan:

- Not part of the current research plan.
- Treat as a future systems project with its own design doc, budget model, and
  dry-run protocol.

## H200 Budget Policy

The $250 Tillicum/H200 budget should be protected for questions that cannot be
answered on A40/L40S.

Use cheaper GPUs for:

- Fixing OOMs.
- Running 1M/3M/5M/10M.
- Evaluating checkpoints.
- External embedding checks where model memory allows.

Use H200 only for:

- A 30M/100M run whose smaller-scale evidence passed the gate.
- A measured throughput experiment that requires H200-specific kernels.
- A final training run with a written abort condition.

Abort H200 jobs if:

- No checkpoint is written by the first scheduled checkpoint interval.
- Validation loss is NaN or flat because labels/tokenization are broken.
- GPU utilization is low because the DataLoader is starving the device.
- Peak memory leaves less than 10 percent headroom and CUDA retry logs appear.

## Success Criteria

The current phase is successful when:

- All 16 v1.2 runs either complete or have documented, reproducible blockers.
- At least one token-transformer encoder trains without the full-logit OOM.
- The comparison table includes PCA and scVI.
- The dynamics report says whether value-aware self-supervised CellFM preserves
  dynamic structure better than supervised and classical baselines.
- The next scale decision is a yes/no statement backed by metrics, not ambition.
